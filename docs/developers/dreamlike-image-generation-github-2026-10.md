# 写实梦境风景：GitHub 调研

调研日期：2026-10-18。范围：官方仓库与作者文档。此次仅研究，不安装模型、不修改生图服务、不部署。下文的审美流程是针对 Studio 的设计建议，不是模型官方承诺或实测排名。

## 结论

针对用户喜欢的古院花树，重点是先保住低机位朝天仰拍、树干透视与屋檐框景，再调整花木、天空和光线。建议把「构图参考」「材质要求」「梦境变化」分开控制，并且一次只改一个主变量。堆叠“绝美、梦幻、8K”不能代替这些约束。

GitHub 上值得借鉴的是可复用的制作流程，而非某个保证出片的“梦境模型”：结构条件负责约束布局，图像提示提供视觉参考，编辑模型负责替换内容，最后筛选和精修。

| [Qwen-Image](https://github.com/QwenLM/Qwen-Image)                | 图像生成与编辑，Edit 2509 / 2511 示例支持多图输入；官方提供编辑提示改写流程                   | 是独立后端的编辑候选，适合比较多参考下的内容替换。原始 Edit 与后续多图版本能力不同；官方对改写提升稳定性的建议不能视为构图保证。                                     |

## 当前 Codex 路线：先改善流程

项目上下文：Studio 当前通过 Codex 内置生图，并非 ComfyUI；没有已接入的 ControlNet、IP-Adapter 或种子控制。以下建议可先使用当前参考图和提示组织方式实践，不能把文字约束包装成真正的几何锁定。

1. **固定构图母版。** 选用户认可的原始仰拍版本作为每张候选的起点，而不是连续编辑上一张候选。明确树干从画面下缘进入、树冠覆盖头顶、屋檐只作边缘框景、画面不出现地面与地平线。
2. **把写实要求写成可观察特征。** 自然生长的不对称分枝、花簇疏密差异、树皮裂纹、叶片透光、真实阴影与天空亮度关系；避免全局发光、塑料花瓣、所有区域同样锐利。
3. **只增加一种梦境线索。** 例如薄雾中的晨光、蓝调时刻的淡月、雨后花瓣上的微光。梦幻来自光色与空间层次，材料仍保持摄影质感。这是审美建议，并无通用最优参数。
4. **分批比较。** 第一批固定树种和构图，只比较晨雾、雨后、蓝调；选中后第二批再比较樱花、蓝花楹、银杏。每批维持同一参考与画幅，减少同时改变树种、天气、时段、机位造成的混淆。
5. **先筛构图再看氛围。** 检查朝天角度、屋檐边界、主干走向，其次检查树木可信度与光线。失败构图不要靠后续无限精修挽救。
6. **版本记录保存配方。** 建议记录参考版本/图片、提示、批次变量和结果；有真实后端参数时再保存模型、种子、控制强度、工作流版本。目前不能虚构尚未暴露的参数。

可试的提示骨架：

> 以参考图片为构图依据，保留贴近树根、镜头朝天的强烈仰拍透视，树干从下缘向上延伸，树冠在头顶展开，深色古建屋檐只在四周围合天空，不出现地面或地平线。将树替换为【树种】，保持真实树皮、自然分枝、疏密不均的花叶和合理透光。氛围为【一种光线/天气】，梦境感来自克制的光色和空气层次，保留自然摄影质感。其他结构尽量不变。

这是一份可测试的提示，不承诺精确复制镜位。

## 长期方案：可选的 ComfyUI 后端

保持 Studio 的对话、批次、版本和图片浏览体验，另将选定工作流作为后端执行器。建议先做两个对照工作流，而不是一开始叠加所有插件：

- **结构优先：** 参考图 → 适配模型的深度/边缘条件 → 文字描述树种和氛围 → 多候选 → 筛选。深度更侧重空间布局，细碎边缘可能连旧花叶轮廓也一起约束；换树种时需要实测控制强度。
- **编辑优先：** 参考图 → 图像编辑模型 → 明确局部变化 → 多候选 → 筛选。适合直接比较换树、换天空与换光线时的结构漂移。

若需要外观参考，可在兼容工作流加入 IP-Adapter；先检查竖幅输入预处理。需要局部修复时再加补绘，需要输出尺寸时最后处理放大。不要将放大或重打光当作修复错误构图的替代。

接入前需要实测 GPU 成本、延迟、许可证与工作流稳定性。这是新的独立推理服务方案，不是给当前 Codex 调用增加几个参数。建议以原仰拍母版和固定的三组编辑任务做盲测，比较构图保留率、真实感、梦境氛围、失败率与单张成本，再决定是否值得接入。
