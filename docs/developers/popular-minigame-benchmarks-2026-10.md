# 热门小游戏生成验证选题

核验日期：2026-10-15。本轮通过公开网页检索筛选，依据开发商官网、官方商店和原作者说明核验。下文是选题与验收方案；没有据此宣称 OpenGame 已经通过测试。累计下载、累计玩家、活跃用户和评价数是不同指标，不能相加或直接排名；这些游戏也不全是近期新作。

## 首批选择

建议先生成三个独立项目，再选其中一个做一次修改回归。这样覆盖离散规则、连续物理和实时动作，能比重复生成几款三消更快发现平台的能力边界。使用原创名称与画面，依据公开核心玩法独立实现，不向生成器提供原作源码、截图或素材。

## 第一版生成说明

以下数值、主题和练习关是本轮主动定义的测试规格，不是对原作所有规则与平衡参数的精确还原。每款都应提供可正常反复游玩的标准局；练习关用于教学，也让验收不依赖随机运气。

### 《方块港湾》

制作中文 2D 网格益智游戏，画面为干净的港口货箱主题。8×8 棋盘，下方始终保留一组最多三个待放形状，三个全部使用后再生成新组。形状不能旋转。鼠标和触摸都支持“先选形状，再点棋盘左上锚点”，可额外支持拖放。显示合法放置预览；越界或重叠时拒绝，棋盘、手牌和分数不变。

合法放置后，每个新占格加 1 分；同一步所有完整行、列同时消除，每条加 10 分。相交格只清除一次。只有当前所有剩余手牌均无合法落点时才判失败，结束后可重新开始。分数、消除行列数和最高分清楚可见；不要求联网榜单。

增加“新手练习”：第一行预先占满前七格，待放单格可以补最后一格，方便确认清行；同时包含重叠尝试和一次清行清列的教学场景。标准局仍从正常布局开始，不能把演示脚本当作游戏。

### 《星球合成站》

制作中文单人 2D 物理合成游戏，使用原创矢量星球，不使用原作水果图。玩家移动投放位置，点击或按空格落下一颗星球，支持左右键和触摸。提供当前与下一颗预告、至少六个可区分等级、合成分数与重新开始。

星球有重力，与容器底部、侧壁和其他星球碰撞；两个同等级星球接触后移除二者并生成一个高一级球。单个物体同一结算批次不能被重复合成。最高等级不继续越界升级。按新等级给予递增分数。投放有短冷却，长按或连续点击不能在同一帧无限创建物体。

标明危险线。新球投放后保留落下宽限；已入场的球持续越过危险线两秒才失败，短暂弹跳不立即判负。结束后停止投放、显示结算。新局必须清空物体、速度、计时器与分数。提供可重玩的“合成练习”，前两颗固定为最低等级，便于主动将二者落在同一位置并观察真实合成。

### 《快递穿行》

制作中文 2D 顶视角街机游戏。玩家是原创快递机器人，地图九列，包含安全区和双向移动车道；每次方向键或触摸方向按钮移动一格。角色前进后镜头逐步跟随，持续生成新道路并移除远离镜头的道路与车辆。

分数只取本局达到的最远前进行数；左右移动、后退再前进不能重复刷分。道路上的车辆按时间持续移动，碰撞即结束；最高距离、当前分数与重开入口清楚可见。起始安全区有清楚的操作提示，第一条车道速度较慢且留有可通过的空档。提供暂停/继续，暂停时车辆、角色和计时都停止；切换页面回来不应让车辆瞬移穿过玩家。

标准局随机生成，道路布局应留出合理间隔。提供固定开局的“练习路线”，方便观察躲车、碰撞和计分。首版不加入河流、铁路、抽奖或角色商店。

## 验收矩阵

验收动作通过实际玩家输入完成；涉及随机或极端状态时采用明确的练习布局，或在项目中保存独立规则检查。不得仅凭标题、启动成功或生成器自述判通过。

| 用例                               | 必须看到的结果                                            | 常见失败信号                               |
| ---------------------------------- | --------------------------------------------------------- | ------------------------------------------ |
| 方块：选单格补齐练习首行           | 放置成功、整行清空、分数增加 11、消除计数增加 1           | 只有动画没有清除；消除后仍占用；分数重复加 |
| 方块：尝试重叠和越界               | 拒绝放置，手牌、棋盘、分数保持不变                        | 错误操作扣块或加分；拖放坐标与画面不一致   |
| 方块：最后一格同时补满行列         | 两条同时消除，交点只处理一次                              | 先清行导致漏判列；出现负占用或重复奖励     |
| 方块：一块放不下、另一块仍可放     | 对局继续；只有所有剩余块都放不下才结束                    | 选中大块后立刻错误判负                     |
| 合成：两颗同级落到同一点           | 真实下落后变为一颗高一级球，只结算一次                    | 两球消失不生成；同一碰撞生成多颗；穿透地面 |
| 合成：不同等级相碰与连续投放       | 异级保留，冷却有效；物体留在容器边界内                    | 按距离合成任何球；长按指数增长；球卡在半空 |
| 合成：短暂越线与持续越线           | 短暂弹起不判负；达到持续阈值才结束                        | 初次落球即失败；越线永久不结束             |
| 穿行：前进、后退、再前进           | 只按最远行数计分，不能重复刷分                            | 每次按键都加分；镜头与碰撞坐标错位         |
| 穿行：车辆撞到角色                 | 明确结束，分数冻结；新局重新可玩                          | 穿车不死；未接触就死；结算后还能走         |
| 穿行：暂停后继续、连续重开三次     | 暂停真正冻结；新局恢复正常速度与一次输入一步              | 暂停仍被撞；重开后速度或按键监听翻倍       |
| 通用：Safari 与 Chromium、宽窄窗口 | 核心棋盘与操作按钮完整可见，点击落点一致，能进入/退出全屏 | 控件被裁切、输入被页面滚动吞掉、横向溢出   |
| 通用：发布后再打开分享页           | 发布版本与已验收版本一致，可开始、失败和重开              | 分享加载草稿、旧版本、空白页或仅有静态截图 |

每款至少跑一个完整的“开始—实际操作—计分—结束—重开”回路；连续运行三分钟，查看是否有明显卡顿、无限对象增长或重复事件。浏览器差异、无控制台错误和玩法正确分别记录。人工三分钟体验不等于性能压测或留存验证。

## 一次修改回归

优先对《方块港湾》追加“每局一次撤销”：撤销最近一次有效放置，完整恢复棋盘、手牌、分数与发牌状态。错误放置不能占用撤销机会，清行清列后的撤销也必须有效。初始版本先验收并保存，再提交这次修改；重跑原有清行、非法落点和死局用例，验证修改没有破坏核心玩法。若首版存在阻断错误，先把该次修改额度用于修复并重新验收，不能一边玩法失败一边加功能。

## 结果记录与知识沉淀

每个实际测试项目应记录原始提示词、项目与版本、生成耗时、构建结果、人工通过/失败用例、浏览器和窗口大小、截图、发布地址，以及修订前后的回归结果。失败用例同样保留，避免只保存成功作品造成幸存者偏差。

可复用的候选经验包括网格同时消除、物理合成去重、危险线宽限、实时暂停与重开清理。只有存在复现步骤和已通过回归的改动才适合进入公共规范候选；先作为带来源的观察保存。三款样本可以暴露具体缺陷，尚不能证明平台支持任意类型游戏，也不能证明共享知识已提升后续生成成功率。
