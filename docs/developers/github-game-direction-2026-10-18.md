# GitHub 游戏方向调研：适合 GPT-6 astra 协作制作的辨识度项目

核验日期：2026-10-18。依据 GitHub 项目维护者的 README、许可文件与项目结构比较；未下载运行、未试玩，也没有 GPT-6 astra 制作这些游戏的实测结果。模型适配与首版范围均为工程判断，不是能力榜单。本笔记沿用仓库 `docs/developers/` 的调研文档惯例。

## 选择

推荐 **Baba Is You 式的规则解谜**，原创项目暂名 **《规则修理铺》**：玩家在机械小镇推动文字铭牌，改变物体的属性，修好通往出口的路线。参考项目选 [Xanonymous-GitHub/BaBaIsYou](https://github.com/Xanonymous-GitHub/BaBaIsYou)，用途是研究规则如何成为可操作对象；首版以原创规则实现、角色和关卡构成。

这个方向的辨识度来自“移动一句话就改变世界”。相较于依赖大量动画、战斗反馈和经济数值的项目，它把主要难点集中在明确、可重复验证的规则交互上，适合让代码代理编写状态转换、撤销、关卡校验和回归测试。规则组合仍然容易产生边界错误，因此必须缩小词汇集，并通过求解回放与实际试玩验证。

## 两个补充参考

**PuzzleScript** 是 MIT 许可的 HTML5 解谜引擎，适合作为小型网格规则原型的备选基础。它与 Baba 式“玩家在运行时移动文字并重写规则”不是同一层概念；不能因为它有规则语言就认为该玩法已经现成实现。若目标是鲜明的中文铭牌视觉、流畅动效和自定义解释反馈，原创 TypeScript 状态核心与独立渲染层更直接；这也是设计判断。[项目](https://github.com/increpare/PuzzleScript)、[许可](https://github.com/increpare/PuzzleScript/blob/master/LICENSE)

**递归推箱子**有强烈的空间辨识度，但本次找到的 [Zygahedron/Parabox-Editor](https://github.com/Zygahedron/Parabox-Editor) 是 Python 关卡编辑器，[Skunkynator/Paraboxical](https://github.com/Skunkynator/Paraboxical) 是 GPL-3.0 的 Godot 编辑器。它们不能被描述成 Patrick's Parabox 完整游戏源码。前者本次未找到明确根许可；不把它列为可直接复用底座。递归世界转换与循环容器的状态定义更难，暂不作为首选。

## 《规则修理铺》首版规格建议

原创差异化优先验证“搬运属性标签并安装到物体上”：例如给墙装上可推标签、给石头装上操控标签。先用三个关卡验证这种交互是否清楚、有趣，再决定是否采用。下列拼句子规格是机制参考与备选；两套交互不同时进入首版，标签方案确定后须统一修改规则与教学。

- **表现**：单屏俯视 2D，奶油白维修台、蓝绿色机械件、橙色文字铭牌；有效句子用发光连线和轻微机械启动动画反馈。角色、图标、音效与地图全部原创。
- **规则**：只支持横向与纵向的“对象—是—属性”。六种属性为操控、阻挡、可推、胜利、危险、漂浮。漂浮仅表达分层碰撞，不增加连续物理。固定步序先移动，再重算规则，再处理接触和胜负。
- **内容**：12 个原创短关卡，先做 3 个验证关，再扩展到 12 个；依次教学移字、改变碰撞、切换操控对象、危险与漂浮，最后少量组合。每关至多引入一个新概念。
- **操作**：方向键或 WASD、撤销、重开、关卡选择、完成进度保存；失去可操控对象时仍能撤销。主动高亮本步改变的句子，避免玩家不知道发生了什么。
- **验证**：每个正式关卡保留一条可执行通关动作序列；规则核心可脱离画面运行，检查确定性、撤销复原、连推、多个操控对象、规则失效和接触判定。有界搜索找到解后用同一个核心回放；搜索超时不能标成无解。
- **边界**：首版不加入 AND/NOT、名词变换、自动生成关卡、联网、自由编辑器或长篇剧情。求解器验证可通关，试玩负责确认提示、难度和乐趣。

首版通过条件：12 关都有回放验证；任意合法动作后撤销能完整恢复；第一次体验的玩家能在前两关理解“改变文字会改变世界”；至少三关产生明显不同的解题思路。项目研究与规格已经明确，本次未创建或实现游戏。
